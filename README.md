# pi-handoff

Session handoffs for the pi coding agent. When a session ends, pi-handoff writes a handoff document and starts a successor session from it — no lost context, no half-adopted subagent runs. Works on a plain pi install; a terminal-tab backend is optional. Community fork of @tifan/pi-handoff.

## How a handoff runs

Two backends, same document. Pick with `PI_HANDOFF_BACKEND`:

| `PI_HANDOFF_BACKEND` | What happens | Needs extra software |
|---|---|---|
| `auto` *(default)* | tab backend if a herdr workspace is detected, otherwise in-process | no |
| `in-process` | writes the document, then opens a new pi session via `ctx.newSession` and sends it the handoff prompt | **no** |
| `tab` | writes the document, then opens a real terminal tab and delivers the prompt into it, with delivery verified | yes — `herdr` (see below) |

On a machine without `herdr`, `auto` resolves to `in-process`: you still get the document and a successor session that has already received the prompt. The tab backend only changes *where* the successor runs and adds delivery verification, parent-tab retirement, and budget auto-close.

## Features

Features that work everywhere:

- **Structured handoff document** — verify-first command list, state with SHAs/paths/task IDs, governing decisions, next steps, suggested skills, open questions. Generated by a model from the real conversation, never from a template.
- **Smart child naming** — naming core from pi-rename: explicit focus > parent session name (prefix stripped) > rename model > first real user message fallback, with synthetic-message filtering.
- **Configurable session_query model** — the `session_query` tool resolves its model from the configured rename model, then the session model.
- **In-flight subagent-run adoption** — budget handoffs list still-active subagent runs with a recovery line, so the successor does not silently abandon them.

Features added by the tab backend (`PI_HANDOFF_BACKEND=tab`, or `auto` on a herdr machine):

- **Verified prompt delivery** — the prompt is sent through `herdr --wait` and cross-checked via status polling, with one automatic retry if delivery is not confirmed.
- **Parent tab retirement** — the originating parent tab is marked `[handed-off]` so you can see at a glance that it has been superseded.
- **Budget-aware auto-close** — when the handoff reason is budget exhaustion, the parent tab auto-closes after 3 seconds. Opt out with `PI_HANDOFF_KEEP_TAB=1`. Voluntary handoffs keep the parent tab open.

## Prerequisites

| Requirement | Needed for | If missing |
|---|---|---|
| pi ≥ 1.3 | everything | — |
| Node ≥ 20 | everything | — |
| A model with tool use | generating the handoff document | `/handoff` reports "No model selected." |
| a skill named `handoff` | customizing the document policy | the **built-in handoff policy** is used and a warning is shown |
| `herdr` binary + `HERDR_ENV=1` + `HERDR_WORKSPACE_ID` | the tab backend only | `auto` falls back to the in-process backend; `PI_HANDOFF_BACKEND=tab` warns and falls back too |

## Install

```bash
pi install ./pi-handoff              # local checkout
pi install npm:@jyyyeung/pi-handoff  # published package
```

Then restart pi (or `/reload`). If you prefer hand-editing, add the package
path to the `packages` list in `~/.pi/agent/settings.json` — but `pi install`
is the supported path.

Optionally install a `handoff` skill (any pi skill whose name is exactly
`handoff`) to replace the built-in document policy with your own.
